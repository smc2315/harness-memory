# Changelog

All notable changes to `harness-memory`. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); the project uses [Semantic Versioning](https://semver.org/) (0.x: minor versions may break).

## 0.6.0-rc.3 — unreleased

Full autonomy, second pass. The rc.2 `dream` sweep was run against the author's dogfood database (356 auto candidates): it activated 154 and left two kinds of rows that no later run could ever lift — 14 rule rows born from decision-only episodes (`evidence_score 0`, parked at `candidate(evidence)` for good) and 7 extractor corrections parked behind one-session `supersede` proposals while the stale claims they correct were activated. Design and numbers: [docs/redesign/full-autonomy-0.6.0-rc.3.md](docs/redesign/full-autonomy-0.6.0-rc.3.md).

### Changed

- **Decision-born rules activate under `full`.** A `pitfall` / `workflow` / `policy` row whose *origin* episode carries the decision marker (`flags.decision`) counts it as `FULL_DECISION_MARKER_EVIDENCE` = 1 toward the `full` evidence bar (`evidence_score ≥ 1`), so every extracted rule with `confidence ≥ 0.7` and a reachable trigger now activates at `advise`. `evidence_score` itself stays 0; a legacy or imported row reinforced by a decision-only episode stays a candidate; `standard` / `shadow` / `off` ignore the marker.
- **Replacement rows resolve under `full`.** An open `supersede` proposal whose target is an auto `candidate` (or `stale` by TTL) and whose replacement passes `decideTier` on its own resolves on one support: the target is superseded, the replacement is activated by `decideProposal` (`accepted by auto_rule (full_autonomy)`) with the usual TTL, sibling `supersede` / `stale` / `revalidate` proposals on the dead target and `activate_*` proposals on the replacement are closed `expired(full_autonomy)`, chained corrections (`T0 ← T ← R`) resolve in the same run from the correction end — a contest whose replacement is itself the target of a resolvable contest is skipped as `candidate_contested` (design §2.1 rule 4b; no budget unit, no report entry) and settled by that contest's chain walk, so `T0` is superseded by the final correction, never by a contradicted middle row; the walk re-reads every proposal before deciding it and skips a hop an earlier hop already closed, so a diamond never throws, `proposalsAccepted` / `proposalsClosed` list each id once and `superseded` lists `T` first, then the chain targets in walk order — and one `full_supersede` audit row is written per superseded row. The `dream` sweep resolves these contests *before* its candidate loop (a contested candidate is never activated first), then re-checks open `supersede` / `stale` proposals on **active** targets against the two-session rule; reconcile step 7 does the same for the rows of the current extraction: for every candidate row the contests on it are resolved first, a replacement row's own contests only when none did; a held (`candidate_contested`) contest is resolved from the correction end (recursion up to `CHAIN_MAX_DEPTH` = 10) and the row superseded through the top chain walk, a contested row whose chain did not resolve in this run is left to the sweep (`tier=candidate:contested`); the outcome of every row of the run a resolution touches is annotated when it is applied — `tier=active; full_supersede=<targetIds>` (walk order) on the replacement, `tier=candidate:superseded(<replacementId>)` (exactly one id, the replacement that superseded it) on each superseded target, `tier=` once per detail. A contest a human rejected (`supersede` / `stale` on the target, `activate_*` on the replacement), a human target, the human-signal rule and a replacement below the bar leave the contest open: the target is swept like any other candidate and the replacement stays parked until the contest expires.
- **`support_sessions` counts (session, 4-hour block) pairs** — the key `distinct_session_count` and the enforcement ladder already use — so the two-session demotion rule fires in a session resumed for days. Level-blind: the rule (`evaluateAutoDemotion`, reconcile step 6 and the sweep's phase 2) has never been gated by `autonomy_level`, so the block-aligned count applies under `standard`, `shadow` and `off` as well — there `decideTier` activates nothing, but a contested active auto row can still be superseded, and its replacement activated, by two blocks, as under rc.1.
- **The two-session rule honours human rejections.** `evaluateAutoDemotion` refuses a target whose `supersede` / `stale` a human rejected (`target_human_rejected`) and a `supersede` whose replacement carries a human-rejected `activate_policy` / `activate_global` (`candidate_human_rejected`), checked right after the target's status and before the session count, under every autonomy level — at extraction time (reconcile outcome detail `support=<count>/<sessions> (target_human_rejected)` / `(candidate_human_rejected)`) and in the sweep's phase 2.
- **`knowledge_kind` follows the episode signals.** A fact the extractor labelled `correction` / `failure_resolution` whose episode carries no correction, remember or failure flag and no `correction_for` is stored as `convention` (outcome relabel `kind_without_signal`): 7-day TTL instead of 30, no `revalidate` grace, no ladder. Migration 024 (`user_version` 24, backup `memory.sqlite.bak-v23`) applies the same rule once to stored auto rows that have evidence provenance (`origin` or `reinforce`; a reinforce-only row counts), whatever their status — a superseded or rejected row is relabelled too, its status and `superseded_by` untouched; human rows, imports, rows without provenance and rows with any signal episode (a signal on a reinforce episode alone keeps the label) are untouched, and no TTL already set is shortened. An imported bullet keeps `knowledge_kind = import`; because an import carries no episode signal, an imported `policy` the extractor labelled as a correction now stays a `policy` (rc.2 turned it into a `pitfall`), its enforcement default unchanged.
- A `supersede` accepted by `auto_rule` gives the replacement `tierTtlDays`: a `decision` / `architecture_constraint` replacement gets 30 days (under `standard`, `shadow` and `off` too, where it got 7: the two-session rule is level-blind), a `task` row 7, a rule `baseTtlDays(kind)`.
- The `full` sweep runs every resolution and activation in its own `SAVEPOINT`: a throw costs that row (reported under `sweptErrors`), never the run's other activations. Sweep resolutions carry the transition reason `full_sweep` and consume neither daily cap, as rc.2 promised for sweep activations; extraction-time resolutions are charged to the run's caps like any activation.
- **Sweep phase 2 keeps the books, and `dream.full_sweep_per_run = 0` leaves it running.** A replacement the two-session re-check of an open `supersede` / `stale` proposal on an active auto target activates (decision effects include `replacement:active`) has its open `activate_policy` / `activate_global` proposals closed `expired` by `auto_rule` with note `full_autonomy` (ids appended to `DreamReport.sweptProposalsClosed`) and gets one `full_sweep_activation` audit row — summary `full sweep: <type> <summary> activated via supersede of <targetId> (evidence N, confidence C)`, `details_json` `{ memoryId, type, evidenceScore, confidence, ttlExpiresAt, proposalsClosed, proposalId, superseded: [targetId] }` — like any sweep activation; such an application makes the `dream` op non-noop. `dream.full_sweep_per_run = 0` now switches off phases 1 and 3 (the resolutions and the drain) only: the two-session re-check costs no unit and still runs. Phase 1 keeps its oldest-first order, and a resolution that throws holds its target **and** every chain target behind it (`chainTargets`) back from phase 3 in that run (`sweptErrors` line `resolution <proposalId>: <message>`), so the retry still finds the chain intact.

### Added

- Two `auto_rule` edges in the state machine, auto rows only: `candidate → superseded` and `stale → superseded` (the latter only with `status_reason = ttl_expired`).
- `DreamReport.sweptSuperseded` / `sweptErrors` (the `hm dream` line and the worker log show them); `ReconcileReport.superseded` (the targets step 7 superseded, chain hops included, in walk order) and `ProcessedEpisode.superseded` / `reconcileSession(…).superseded` (the same list per run, empty outside `full`; in the `processed[]` items of `hm extract --json` / `hm import --json`); the worker's `reconciled` log line gains `superseded=<n>` after `activated=<n>` (fields `episode run status facts accepted created activated superseded proposals escalated remembered noop`); the per-episode line of `hm extract` / `hm dream` (and of `hm import` under `HARNESS_MEMORY_DEBUG=1`) reads `episode <id8> run <id8> <status>[ (raw cache)]: created N, activated N, superseded N, proposals N, outcomes N[, escalated N][, remembered N]`, while the `hm dream` line `full sweep: activated N, superseded N, proposals closed N, errors N` is unchanged; `hm memory:history` prints the decision note of a decided proposal (`accepted by auto_rule (full_autonomy)`).
- `ProvenanceRepository.hasDecisionOrigin`; `src/promotion/replacement.ts` (`checkSupersedeResolution(db, proposalId, { passesTier }, depth?)` — `SupersedeCheckOptions.passesTier` is the caller's rule-5 judgement and is required; `applySupersedeResolution`; `chainTargets`; `CHAIN_MAX_DEPTH` = 10; `SupersedeSkipReason` `candidate_contested`); `CONTESTING_KINDS` (`supersede`, `stale`, `revalidate`) in `src/promotion/proposals.ts`; `humanRejectedContest`; `AutoDemotionResult.reason` `target_human_rejected` / `candidate_human_rejected`; reconcile outcome detail `tier=candidate:contested`.

### Fixed

- On the dogfood dump the rc.2 sweep activated the stale target of a one-session `supersede` and left the correction parked for its whole TTL; rc.3 supersedes the target and activates the correction (4 of the 7 open contests resolve, the other 3 wait for a second block, a human signal, or a replacement that clears the bar).
- Rule rows extracted from decision-only episodes (14 on the dump, among them "do not run build-migration against prod") could never reach the `full` evidence bar; they now activate at `advise` with a 7-day TTL under their true label.

## 0.6.0-rc.2 — 2026-11-26

Full autonomy after the first dogfood run (17 days, one work project): 153 proposals and 356 candidates waited for a review that never happened, 0 `ask` / `deny` decisions in 13,685 `PreToolUse` calls, one ladder escalation. The author's verdict — a tool that needs human intervention will not be used — becomes the default. Design and numbers: [docs/redesign/full-autonomy-0.6.0-rc.2.md](docs/redesign/full-autonomy-0.6.0-rc.2.md).

### Changed

- **`autonomy_level: full` is the new default.** `decideTier` activates at `advise` every row the mechanics can bound: `decision` / `architecture_constraint` with `confidence ≥ 0.7` (no episode evidence needed; `extraction.max_auto_knowledge_activations_per_day` = 10), repo-wide rows and policies (never `confirm` / `deny` automatically), `pitfall` / `workflow` at `evidence_score ≥ 1`. No `activate_policy` / `activate_global` proposal is opened and the daily `SessionStart` digest is not shown; `supersede` / `revalidate` keep resolving on their own. `standard` is the 0.6.0-rc.1 behaviour and stays selectable; `shadow` and `off` are unchanged. rc.1's `hm install` wrote `"autonomy_level": "standard"` into every `config.json`, so `hm install --host claude` now rewrites that one value to `full` when the install manifest says the previous install was pre-rc.2 (and prints it); set `standard` again afterwards to keep the review gate. A candidate whose `activate_*` proposal a human rejected is never activated by the automatic path (it meets the candidate expiry).
- **The ladder climbs only for mistake-exact signatures**, under `standard` and `full`, and `distinct_session_count` counts distinct `(session, 4-hour block)` pairs so a session resumed for days can reinforce a rule. Fire counts never promote a row: in the dogfood data the most-fired rules carried signatures naming the legitimate operation.
- **`soft_deny` at birth for silent writes.** `enforcementDefault` gives `before_tool.auto_enforcement_silent_write` (default `soft_deny`) to an auto pitfall / policy whose signature is `mistake_exact`, whose matched call has `side_effect: write`, learned from a correction or a failure → resolution pair with evidence ≥ 2 and `horizon` not `task`. Everything else is born at `advise` as before. The dogfood set contained exactly two such rows.
- **Extraction eligibility.** An `interrupted` episode with at most two ledger lines (the prompt plus one event) is `no_signal` whatever its flags; a correction cue counts 2 only when the episode corrects a previous turn that had tool calls (a bare cue counts 1); decision-marker-only episodes are extracted at most `extraction.decision_only_per_day` = 5 times a day (`decision_cap`; an episode requeued by a provider outage does not consume the budget).
- **Extraction prompt (`EXTRACTOR_VERSION` 2026.11.v2).** The signature must be the token that was wrong, never the command, table, host or tool the fix also uses; MCP calls name the MCP tool, CLI wrappers in bash name the subcommand; `trigger_signature.side_effect` (`read` / `write`) and `horizon` (`durable` / `task`) are emitted; code-review findings are `architecture_constraint` / `decision`, not `pitfall`.
- **Duplicates reinforce instead of multiplying.** A live row of the same type with an intersecting scope is the twin when the summaries overlap (Jaccard ≥ 0.6), the signature keys are equal or one narrows the other for the same tool, target, kind and negation (`npm test` ~ `npm test --coverage`, not `npm test:e2e` or a negated key), ≥ 2 aliases are shared, or an error-code token is shared and corroborated by overlapping wording (Jaccard ≥ 0.2) or one shared alias. Aliases and error codes never fuse two facts whose signatures name different mistakes. A signature-bearing fact is still never absorbed by a signature-less neighbour: an auto row with the same identity key adopts the signature (`adopted=signature`; never while an `activate_*` proposal on it is open or was rejected, except on a remember turn), a human row only gets the reinforce (`collapsed=identity_key`).

### Added

- Migration 023 (`user_version` 23): `memories.signature_precision` (`mistake_exact` / `noun`, computed once by the validator against the source episode's `tool_ok` lines), `side_effect`, `horizon`; NULL for existing rows (treated as `noun` / `read` / `durable`, so no pre-023 row reaches `soft_deny` through the new rule without a re-extraction). `hm memory:show` prints the three fields.
- `dream` full sweep: under `full`, waiting auto candidates are re-evaluated oldest first and up to `dream.full_sweep_per_run` = 50 of those that pass are activated per run (a row that fails costs nothing; a row whose `activate_*` proposal a human rejected is skipped); a row that activates closes its open `activate_*` proposals (`expired`, note `full_autonomy`). The 0.6.0-rc.1 backlog drains without a command once `hm install --host claude` has flipped the rc.1-written `standard`.
- `signature_precision` is computed over the full episode (not only the lines the 24k-char prompt rendered), with two rules for corrections of a previous turn: a cited `tool_ok` line of the correcting turn counts as a hit (it is the fix, not the mistake), and the corrected turn's tool lines are scanned — a pattern matching two or more distinct calls there is `noun`.
- A `task`-horizon row keeps its 7-day TTL ceiling through reinforce (`computeRevalidation`), fire (`extendTtlOnFire`) and the auto-accepted `supersede` replacement.
- `hm install` reports the effective `autonomy_level` and the rc.1 → rc.2 rewrite on its `config` line.
- Config keys `before_tool.auto_enforcement_silent_write`, `extraction.max_auto_knowledge_activations_per_day`, `extraction.decision_only_per_day`, `dream.full_sweep_per_run`; `TierReason` `knowledge_cap`; skip reason `decision_cap`.

## 0.6.0-rc.1 — 2026-11-08

Release candidate of the v0.6 redesign (branch `redesign/v0.6`). Design: [docs/redesign/spec-v0.6.md](docs/redesign/spec-v0.6.md); build plan: [docs/redesign/implementation-plan.md](docs/redesign/implementation-plan.md); upgrade notes: [docs/redesign/upgrade-from-0.5.md](docs/redesign/upgrade-from-0.5.md).

### Changed (Phase F — direction A′, 2026-11-08 night)

- Auto-learned pitfalls start at `advise` (`before_tool.auto_enforcement` default was `soft_deny`; the old value stays selectable) and climb to `soft_deny` only when a second session reinforces them (`before_tool.auto_escalation`, default `{ enabled: true, sessions: 2 }`; `autonomy_level: shadow` never climbs; a row downgraded by overrides needs a new session). `hm memory:history` shows the climb as `active (enforcement) by auto_rule`; `hm memory:stats` no longer counts escalations as activations.
- The `not_logged_in` guidance says what is true: imported and hand-added rules fire without the CLI login; typing new import bullets and learning from sessions — remember turns included — start after `claude auth login`.

### Added (Phase F)

- **Remember-as-human.** A fact extracted from a turn with an explicit remember request (`remember this`, `기억해`, `from now on` + a rule) that cites that prompt line becomes a human rule at once (`status_reason remember`, at most two per turn): policy with a signature → `confirm`, pitfall with a signature → `soft_deny`, else `advise`. `SessionStart` names such rules for 24 hours with the undo (`hm memory:demote <id>`); `hm memory:list` tags them `[remember]`; V6 / V8 / V12 still apply, and for these facts alone a global rule without a signature passes V3.
- **Recall layer, shipped dark.** Migration 022 (`user_version = 22`) adds `summary` / `summary_kind` to `episodes`; the worker gives every episode a deterministic summary the moment it is queued and the extractor's `episode_summary` (scanned like memory text) replaces it. With `recall.enabled` (default **false**) the snapshot builder writes `snapshot/recall.v1.json` (newest `recall.keep_episodes` = 300 summaries with a serialized MiniSearch index), `UserPromptSubmit` appends up to `before_model.recall.max_items` (2) `[harness-memory] RECALL <date>: …` lines after the memory items (never on `PreToolUse`, never enforced), `hm recall <query>` searches them and `hm status` shows `recall N episodes`.
- **`hm import --from auto-memory`** (`--auto-memory`, `--include-project`, `--memory-dir <dir>`): Claude Code's native auto memory notes (`~/.claude/projects/<slug>/memory/*.md`, `type: feedback`) become human import rows through the ordinary pipeline with `source_ref = import:auto-memory:<file>#L<n>`; directory-wide `--sync`; `MEMORY.md` itself is never imported and counts as host-loaded. Bullets that cannot be typed yet (no extraction CLI) are stored verbatim as `advise` rows. `hm install` reports the project's auto-memory notes and suggests the import.

### Highlights

- **Claude Code is the first host.** harness-memory now runs as nine Claude Code hooks (`SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `Stop`, `StopFailure`, `PreCompact`, `SessionEnd`) — short-lived `node dist/hook.js <event>` processes that read one precomputed snapshot and never open SQLite. Codex follows in 0.6.1, OpenCode (V2 plugin) in 0.6.2.
- **Enforcement at the tool boundary.** Every memory carries `enforcement ∈ {advise, confirm, soft_deny, deny}`; `PreToolUse` maps it to `additionalContext`, `permissionDecision: "ask"` or `"deny"`. A `soft_deny` blocks only the first attempt of a `(memory, tool)` pair per turn; the retry passes and the override is recorded.
- **One write path.** Per-session append-only ledger → turn segments as episodes (the queue) → structured extraction through your own headless CLI (`claude -p --json-schema`, `codex exec --output-schema`) → validation V1–V11 → deterministic, idempotent reconcile → authority-tiered activation → snapshot.
- **Authority as an invariant.** `authority ∈ {human, auto}` is a NOT NULL column without a default; `transitionMemory` is the only status writer and throws `AuthorityViolationError` when the automatic path touches a human row. Pitfalls and workflows learned from one correction or one failure → resolution pair activate on their own (`authority = auto`, TTL 30 / 7 days, trust multiplier 0.65 → 0.95); policies, global rows and every demotion of a human row go through proposals and `hm review`.
- **Optional dense retrieval without a daemon.** An idle-exit embedding helper (named pipe / Unix socket, exits after 15 idle minutes) serves `before_model`; `PreToolUse` stays snapshot-only. Extractor-provided `aliases` (including Korean) are indexed lexically so non-English prompts reach memories without embeddings.
- **Operability.** `hm status` (one line), `hm doctor [--fix] [--self-test] [--host-debug]`, `logs/hooks.log` with one line per hook call and p95, `install-manifest.json`, `db:rollback`, `snapshot:rebuild`.

### Changed

- `MemoryRepository.create()` requires `authority` and `sourceKind`; duplicate detection considers live rows only (`candidate`, `active`, `stale`) and `reviveTerminal` re-creates a fact whose earlier rows are terminal; `update()` rejects `status` and `authority`.

### Fixed (v0.5 defects, see `docs/redesign/core-review-v0.5.md`)

- R1 — LLM candidates could never be promoted (evidence count always 0): provenance rows and derived counters are written in the same savepoint as the row, and `decideTier` reads them.
- R2 — LLM memories were hard-coded to `**/*` + `before_model` and never reached `before_tool`: scope, triggers and trigger signatures are required schema fields; legacy rows are flagged `needs_scope` with `fix_scope` proposals.
- R3 — extraction ran at most once per process lifetime: every closed episode is queued and a detached worker drains the queue.
- R4 — an LLM `supersede` / `stale` demoted human memories without review: the LLM can only propose; `transitionMemory` refuses automatic actors on human rows.
- R5 — a duplicate fact threw and the batch retried forever: live-only duplicate detection, reinforce instead of throw, per-fact savepoints, `write_ops` idempotency, dead after three attempts.
- R6 — template-text candidates: regexes only set flags; no candidate is synthesized without the extractor.
- R7 — two write paths consuming each other's inputs: one input stream (ledger → episodes) and one consumer (`worker extract`).
- D1–D7 — resident database overwrites, mem0-style prompt without scope / tools / triggers, 300 / 4,000-char truncation and mis-attributed sessions, reinforcement without revalidation, scope-only policy engine without a rule writer, review inbox in the system prompt, 2 KB evidence per tool call.

### Fixed (Phase D adversarial review)

Five review dimensions (write path, hook hot path, concurrency and crash safety, security, cross-module consistency) produced 47 findings; 34 survived two independent refutation passes each and were fixed by area, every fix with a test (`docs/redesign/phase-d-notes.md`).

- **Redaction and scanning.** `redactCredentials` now catches env-var style keys (`DB_PASSWORD=`, `AWS_SECRET_ACCESS_KEY=`, `$env:DB_PASSWORD =`), quoted JSON / YAML keys, camelCase keys (`accessToken`), credentials in a URL of any scheme, `Authorization: Basic`, `curl -u`, `--password`, `mysql -p…`, Stripe / GitHub fine-grained / GitLab / npm / Slack app tokens, keeps `$VAR` references and stays linear on 200 KB inputs. The content scanner (V6) shares the key boundary, adds Korean injection cues (built NFKD because it scans NFKD text), "do not follow the user" and a block-severity control-character pattern. `scope_refs`, `failure_sig` and `program_token` are redacted and capped (256 chars per token, 4,000 in total); rendered memory text drops ANSI / C0 / C1 controls.
- **Extraction prompt.** Recorded events, the previous turn, the last assistant message and the existing-memory list sit inside data fences under an explicit "recorded data versus instructions" section; event ids are positional over the full line list, so a cached raw output resolves to the same ledger lines whatever the memory list did to the drops; import episodes are create-only (`propose_*` relabelled); the worker refuses `import:<path>` sources outside the project root and keeps the bullet text in `raw/` for retries, redacted.
- **Write path.** The two-session `propose_supersede` auto rule is reachable (a replacement's live twin supports the open proposal; `evaluateAutoDemotion` supersedes the target and activates the replacement); provider-level probe failures and spawn errors requeue without burning an attempt; `extractLoop` continues when a lease batch is entirely `no_signal`; the worker rescans `queue/` after releasing `worker.lock` (§9.3 E); an incomplete queue descriptor is renamed `.bad` instead of wedging every later lease; embeddings are computed lock-free and stored in a short lock session (backlog capped at 64 rows per run); the idle sweep re-checks the state file right before advancing and follows hook-core's segment semantics; a legacy candidate whose stored text fails the scanner is reinforced but never auto-activated (`tier=candidate:security`).
- **Proposals.** Rejecting a `revalidate` stales the row (`ttl_expired`); accepting a `supersede` whose candidate is no longer live, or a `fix_scope` / `fix_signature` without a payload, is refused with `ProposalNotApplicableError` before anything is written; a rejected `fix_signature` is not re-proposed for 30 days; V11 reachability uses the same tool-glob resolver as the validator and the PreToolUse matcher.
- **Hot path.** `PolicyEngine.fromSnapshotRules` reuses each derived rule's precompiled signature from the snapshot — no minimatch load and no regex-safety sampling in a `PreToolUse` process (`hm eval:latency` p95 93–96 → 84.5 ms on the development machine); manual rules fire once per turn like memories (`rule:<code>|tool` in `firedKeys`); command canonicalization is memoized per hook; the launcher and `spawnDetached` absorb late asynchronous errors (exit 0, no host-visible hook error); a correction typed after a resume / compact marker still sees the failed previous turn; stale `locks/worker.pid` files (older than 2 h, or a reused pid) no longer disable the POSIX hooks.
- **Concurrency.** `db.lock` takeover is a compare-and-swap on `owner.json` (rename, byte-equal check, exclusive create) instead of remove-and-recreate; `Store.withWriteLock` fences the save with `stillHeld()` and throws `LockBusyError` rather than writing after a lost lock; `cleanOrphanTmp` sweeps `queue/`, `state/` and `raw/`; the dream GC removes orphan `import-*.json` descriptors.
- **Install and CLI.** `hm install` writes `.harness-memory/.gitignore` (`*`), follows worktree / submodule `.git` pointers to the real `info/exclude` (and warns when it cannot), runs npm and the `claude --version` probe without `shell: true` (the bundled `npm-cli.js` through `process.execPath`; `.cmd` shims as one quoted command) and never runs `npm install` inside the project when the package root is unknown; `hm doctor` gained `install.state_ignore`, `install.git_exclude` and the embedding rendezvous path (warning when a Unix socket path is over the limit); the POSIX helper socket lives in `$XDG_RUNTIME_DIR` / tmpdir; every registry usage string names the flags the command accepts (pinned by `test/cli-registry.test.ts`).

### Fixed (first CI run follow-up, 2026-11-09)

- V5's time budget no longer depends on the machine or on its load, and it judges every pattern against a reference of the same shape. The static check also refuses more than `REGEX_AMBIGUOUS_LIMIT` = 3 ambiguous quantifiers in one alternative (`a.*a.*a.*a.*a\.b`: one 128 B sweep took 1.1 s and a sweep cannot be interrupted). The samples add digit runs and the pattern's literal text without its last word, sparsely repeated, so a `prefix .* a .* b` shape backtracks from every prefix; they run as a ladder (128 B … 4 KB, `REGEX_STAGE_BYTES`): at each stage one sweep within the floor (`REGEX_BUDGET_MS` = 2 ms at 4 KB, proportionally less below) passes at once; otherwise the pattern passes when its fastest of `REGEX_BUDGET_ROUNDS` = 5 sweeps is within `REGEX_BUDGET_RATIO` = 2.5× the reference pattern `ref .*\.x` swept over its own samples alongside, with a timed round as long as the candidate's first sweep — so a slower machine, a loaded one or another CPU architecture moves both numbers together — and a first sweep beyond 50× the budget is refused at once. The first GitHub Actions run had rejected `curl .* \| (ba)?sh` on macOS and ubuntu / Node 20: the pattern is quadratic on V5's seed sample (0.8 ms per 4 KB sweep on the author's desktop), and the fixed 2 ms line accepted it here while refusing it on runners 2–3.5× slower under the suite's own load. A linear scan was tried as the reference and dropped: on the Apple-silicon runner the accepted fixtures cost 342–523× a linear scan against 76–179× on x64, while the cost of `cat .*\.env` relative to `[a-z]+[0-9]*\s+x` stayed within 1.6× across every native environment. Against the reference pattern the accepted fixtures cost ≈ 0.5–0.9× and the every-position quadratics (`[a-z]+\s+[0-9]+`, `\d+\s+\d+`) ≥ 7× on the author's desktop; they are refused everywhere, now at 128–512 B in a few milliseconds (the old loop's two 4 KB rounds took ≈ 35–105 ms). `cat .*\.env` and `curl .*\|.*sh` join the accepted fixtures, `\d+\s+\d+` leaves them. `scripts/regex-budget-calibration.mjs` and the `calibrate.yml` workflow (manual, and on pushes that touch the budget code: ubuntu, Windows, Intel and Apple-silicon macOS, native and interpreter) measure the ratios wherever the budget must hold.
- `hm import --from auto-memory` on a case-insensitive Linux mount (WSL `/mnt/c`, ext4 casefold, CIFS): `realpath(3)` keeps the caller's spelling there, so the memory directory's refs and `--sync` prefix could differ by case between runs; the directory's on-disk name is now taken from the projects listing (exact match first, then case-insensitive), and symlinked or junctioned project directories are listed too. An explicit `--memory-dir` is still canonicalised by realpath alone — spell it the same way across runs there. The case-different-root test, which expected no match on case-sensitive volumes although the case-insensitive scan (`scan_case`) finds the directory, was corrected.

### Fixed (fresh-machine review, 2026-11-09)

Installing the packed tarball into fresh npm prefixes on Windows 11 and WSL Ubuntu 22.04 (Node 24 and 20; ASCII, Korean-and-space and v0.5-database projects) passed end to end — install, self-test, direct hook calls, a `deny` decision, migration from `user_version` 9, uninstall. A review of the code for fresh-machine assumptions found six defects, each confirmed by an independent verifier (`docs/redesign/phase-f-notes.md`, "Fresh-machine verification"):

- The node binary pinned into the hooks is resolved through symlinks and Windows junctions (`stableExecPath`): under fnm (one junction per shell), nvm-windows (`C:\Program Files\nodejs` → the active version) or Scoop the hooks kept a link that moved with the next `nvm use` or vanished with the shell. `hm install` warns when the binary lives in a Homebrew Cellar (`brew upgrade node` removes it; `hm doctor --fix` repoints) and when the hook script sits under a per-version directory (pnpm's `.pnpm`, npx's `_npx`, yarn's `.yarn`; the path dies with the next upgrade).
- Shell-form hooks for PowerShell (Claude Code older than 2.1.139 without Git Bash, or `--hook-form shell`) carry the call operator `& "<node>" "<hook.js>" <event>`; PowerShell printed the quoted command instead of running it, so every such hook exited 1. `uninstall` and `doctor` recognise the new form; an entry written by the old form is replaced by re-running `hm install --host claude` (`hm doctor --fix` does not detect it).
- The worker's allowlisted environment forwards the extraction CLI's own auth and routing: `CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CODE_USE_BEDROCK` / `USE_VERTEX` / `SKIP_*_AUTH`, `CLOUD_ML_REGION`, `AWS_*`, `GOOGLE_*`, `NODE_EXTRA_CA_CERTS`, `SSL_CERT_FILE` / `SSL_CERT_DIR`, `REQUESTS_CA_BUNDLE`. A `claude` authenticated through any of them probed `not_logged_in`, and the guidance sent the user to a login they had already done. `CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT` and `CLAUDE_CODE_EXECPATH` stay dropped.
- A re-run of `hm install` keeps the first run's record of having created `.claude/settings.local.json` and added the git exclude line, so `hm uninstall` after a re-install removes both again (it used to leave `{}` and the line behind).
- A brand-new database is reported as `v22 (created)`, not `(migrated from v0)`; an existing file at `user_version` 0 keeps `migrated from v0, backup …`.
- Documentation for installing the release candidate on a new machine: npm's `latest` is still 0.5.1 (the OpenCode plugin), so the README, README.ko and the upgrade note install the GitHub pre-release tarball; `hm` not on PATH, the Windows PowerShell execution policy, Homebrew / nvm / fnm / pnpm / WSL notes, the hook-error escape hatch, env-based CLI logins, moving to another machine, the cost of `--with-embeddings`; schema version 22 everywhere it still said 21; a Korean new-machine checklist, `docs/setup-new-machine.ko.md`.

### Known limitations (0.6.0-rc.1)

- `npm audit --omit=dev` reports one moderate advisory, minimatch GHSA-g3hv-75wg-m249 (globparts amplification). The fix is minimatch 11, whose module shape changes break the lazy `createRequire` glob compiler and the regex sources stored in snapshots; the transitive brace-expansion advisories were fixed in the lockfile. Exposure is small: the matcher only compiles patterns the extractor proposed and V5 / V10 accepted (≤ 200 chars, specific), never user input at hook time. Revisit when the hook bundle moves to its own glob compiler.
- `hm install --with-embeddings` runs `npm install @xenova/transformers` inside the installed package directory, which pulls that manifest's devDependencies too (≈ 350 MB and 17 s on a fast machine, measured on the rc tarball), needs write access there (a `sudo`-installed prefix refuses) and is undone by the next package upgrade. Workaround: `npm install -g @xenova/transformers` next to the package (with `sudo` where that prefix needs it; Node resolves it from the parent `node_modules`) and `embeddings.enabled: true` in `config.json`; re-run with `--with-embeddings` after upgrading. Never `sudo hm install`: it would leave root-owned files in the project. A dedicated, upgrade-proof directory under `~/.harness-memory/` is planned for 0.6.1.
- Live `claude -p` extraction has run in two synthetic sessions only (six calls on the `sonnet` alias, English episodes plus one Korean turn; see docs/redesign/phase-e-notes.md); the replay provider covers the tests, and the dogfood weeks the release gate asks for have not started. The `nested_refusal`, `invalid_output` and `probe_timeout` classifiers have replay / fake coverage only.
- The exec-form hook minimum (Claude Code 2.1.139) is inferred from release notes; `--hook-form shell` is the escape hatch.
- The worker-pid recursion guard is a no-op on Windows (the environment guard `HARNESS_MEMORY_DISABLE=1` covers nested calls on every platform); on POSIX it ignores pid files older than 2 h and pids that started after the file was written. The worker still writes `worker.pid` in place and does not remove it on SIGTERM.
- The 80 ms dense budget may be too short for a cold helper; `before_model` then degrades to lexical-only for that turn.
- `eval:live` (the live three-arm evaluation) is registered but not implemented in this build; every other command runs.
- `hm eval:latency` measures p95 ≈ 85 ms on the development machine (Windows 11, Node 24, `node -e 0` ≈ 50 ms) after Phase D took minimatch off the `PreToolUse` path; the 90 ms gate holds there with a few milliseconds to spare, and Node start-up remains the dominant cost.
- `fix_scope` / `fix_signature` proposals can be rejected but not accepted in this build: no CLI editor collects the scope / triggers / signature payload yet (`hm proposals:accept` reports `payload_missing`).
