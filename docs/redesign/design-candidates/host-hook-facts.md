# Host hook fact sheet (Claude Code / Codex / OpenCode)

Verified 2026-11-08 against code.claude.com/docs (hooks, cli-reference, headless, plugins-reference, memory), learn.chatgpt.com/docs (hooks, non-interactive-mode) and opencode.ai/docs/build/plugins. Produced by the redesign workflow's facts agent (which had no file-write tool, so its structured output is transcribed here) and extended with the host-feasibility critic's re-verification and measurements on this Windows 11 / Node 24 machine. The final spec carries the same facts inline in §8.1; this sheet is the standalone reference.

## 1. Corrections to redesign-brief.md section 6

1. **Timeouts.** Claude Code command hooks default to 600 s (not 60 s). Agent hooks 60 s, prompt hooks 30 s, UserPromptSubmit command hooks 30 s. SessionEnd hooks share a 1.5 s budget (raisable to 60 s per hook). PostToolUse hooks past ~10 s are killed unless `async`; async hooks are killed at `claude -p` teardown. Codex SessionEnd / Interrupt default to 1 s (max 3 s) and unfinished background hooks are cancelled at session end. Consequence: extraction can never run inside SessionEnd, PreCompact or an async Stop hook. The only robust shape is a detached one-shot worker (`detached: true, stdio: 'ignore', unref()`).
2. **PostToolUseFailure** (Claude Code only) carries no `tool_response`. Fields: `error` (string), `is_interrupt` (optional bool), `duration_ms` (optional), plus `tool_name`, `tool_input`, `tool_use_id`.
3. **Codex has no PostToolUseFailure.** Its event list: SessionStart, SessionEnd, PreToolUse, PermissionRequest, PostToolUse, PreCompact, PostCompact, UserPromptSubmit, SubagentStart, SubagentStop, Stop, Interrupt, PreModelRequest, PostModelRequest. PostToolUse runs after non-zero Bash exits, so failures must be inferred from `tool_response`.
4. **PreToolUse decision control.** Claude Code does not accept top-level `decision: "block"` on PreToolUse. Block with `hookSpecificOutput.permissionDecision` = `deny`, or exit 2. `permissionDecision` values: `allow`, `deny`, `ask`, `defer`. Codex accepts only `allow` and `deny`; `ask` marks the hook run failed.
5. **PreToolUse `additionalContext` is not pre-execution.** It is "added to Claude's context alongside the tool result" and read on the next model request. Only `permissionDecision: ask` (reason shown to the user) and `deny` (reason shown to the model) act before the tool runs. A "warning before the mistake" therefore requires ask or deny, not context injection. This is the single most consequential correction for harness-memory's wedge.
6. **`additionalContext` coverage.** Claude Code also supports it on SubagentStart, UserPromptExpansion, PostToolUseFailure, PostToolBatch, Stop, SubagentStop, PostModelSwitch. Codex: SessionStart, SubagentStart, UserPromptSubmit, PreToolUse, PostToolUse, and Stop-family feedback. On Stop, `additionalContext` or a decision continues the turn; on PreCompact, stdout becomes compaction instructions. Review digests and warnings must never be emitted on Stop or PreCompact. `systemMessage` is user-visible only.
7. **Config locations.** Claude Code: `~/.claude/settings.json`, `.claude/settings.json`, `.claude/settings.local.json`, managed policy settings, skill/subagent frontmatter, and a plugin manifest `hooks` key. Codex: `~/.codex/hooks.json`, `<repo>/.codex/hooks.json` (loads only when the project `.codex/` layer is trusted); every non-managed hook needs hash-bound trust via `/hooks`, re-trusted after each binary update. Hooks are enabled by default under feature key `hooks` (`codex_hooks` is a deprecated alias).
8. **Plugin marketplace.** In-session: `/plugin marketplace add owner/repo`. Shell: `claude plugin marketplace add <owner>/<repo>`, then `claude plugin install <plugin>@<marketplace>`. Marketplace file: `.claude-plugin/marketplace.json` (name, owner, plugins[]).
9. **Claude Code stdin fields.** Confirmed: `session_id`, `transcript_path`, `cwd`, `hook_event_name`, `tool_name`, `tool_input`, `tool_response` (PostToolUse), `tool_use_id`, `prompt` (UserPromptSubmit), `stop_hook_active` (Stop/SubagentStop). Also present: `permission_mode`, `prompt_id`, `effort`, `scratchpad_dir`, `last_assistant_message` (Stop/SubagentStop).
10. **Transcripts are not a state store.** Claude Code's transcript JSONL is an internal format that may change between versions, is written asynchronously, may lag, and is not guaranteed to contain the final message at Stop. Codex documents its rollout format as unstable. Use `last_assistant_message` and hook payloads; treat `transcript_path` as an opaque pointer.
11. **Codex event fields.** `tool_input` confirmed; `tool_response` on PostToolUse only; `transcript_path`, `model`, `permission_mode` present. Shell commands match as `Bash`; `apply_patch` matches as `Edit|Write`. Up to eight concurrent async hooks. PreModelRequest / PostModelRequest exist (a true before-model hook, but PreModelRequest carries no `additionalContext`).
12. **Codex transcript path.** The `~/.codex/sessions/` JSONL claim is third-party only; official docs do not confirm it.
13. **`claude -p --bare`.** Bare mode skips hooks, plugins, MCP and CLAUDE.md but never reads OAuth credentials and requires `ANTHROPIC_API_KEY`; Anthropic says it will become the `-p` default in a future release. Subscription-based extraction therefore cannot use `--bare`; recursion must be guarded by an env var checked first by every hook, `--settings '{"disableAllHooks":true}'`, `--tools ""`, `--disallowedTools "mcp__*"`, and an allowlisted env that strips every `CLAUDE*` key (Claude Code sets `CLAUDECODE=1` and `CLAUDE_CODE_CHILD_SESSION=1` in hook subprocesses, and a nested `claude -p` inheriting them has been reported to refuse or hang).
14. **Node is not guaranteed.** Claude Code and Codex are native binaries; `node` on PATH is not guaranteed and nvm/volta paths move. Hooks should be registered exec-form with the absolute `process.execPath`; shell-form strings on Windows without Git Bash run under PowerShell, where any exit code other than 0 or 2 can block the tool.
15. **OpenCode plugin API.** The documented API is V2 (`Plugin.define({id, setup(ctx)})`, `ctx.tool.hook`, session `context` hook, `event.subscribe`); V1 names (`tool.execute.before`, `session.idle`) are a compatibility shim since 1.18.29 and `session.idle` is unconfirmed.
16. **"Zero native dependencies" is currently false.** `@xenova/transformers@2.17.2` depends on `sharp` (native) and optionally `onnxruntime-node`. Keep embeddings optional (`install --with-embeddings`) and native code off the hot path.

## 2. Measurements (Windows 11, Node 24.14, this machine)

| Step | Cost |
| --- | --- |
| Bare Node process spawn | ~36 ms |
| sql.js init + open of a 1.2 MB DB | +53 ms |
| `@xenova/transformers` import (before any model load) | +116 to +204 ms |
| minimatch import | +11.5 ms |
| Read + parse 268 KB snapshot (300 memories) + 300 precompiled RegExp tests | +5 ms |

Consequence: a ~100 ms PreToolUse budget is reachable only with exec-form registration, one bundled entry, no sql.js / minimatch / transformers import in the hook, precompiled scope regexes and a sub-300 KB snapshot. Hooks are snapshot-only readers; SQLite writers are the detached worker and the CLI.
