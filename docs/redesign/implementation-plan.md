## 1. Scope of v1

In: Claude Code host (hooks + install), the whole write path (ledger → episode → extraction → validation → reconcile → tiers → consolidate), snapshot read path (`before_tool`, `before_model`, `session_start`, `after_tool`), the idle-exit embedding helper for dense retrieval in `before_model` (+ extractor-provided `aliases` indexed lexically), the CLI listed in spec §11, `eval:latency`, `eval:replay`, migrations 017–021, legacy-DB upgrade, replay fixtures and the ops test suite.

Out (later releases, keep the seams): Codex host adapter (`hosts/codex.ts`; the `codex` extraction provider is cheap and IS in scope), OpenCode V2 plugin, global DB sync, auto↔auto automatic merge, snapshot buckets, `eval:live`.

Deviation from the spec decided by the author on 2026-11-08: dense retrieval stays in the read path for `before_model` through a self-terminating helper process (spec §6.1 said "dense off in hooks"). `PreToolUse` remains snapshot-only (no model, no socket). Spec §1.2's "no resident daemon" is re-read as "no installed service, no fixed port; the helper exits after `embeddings.idle_exit_minutes` of inactivity".

## 2. Conventions (all agents)

- TypeScript strict, ESM, `moduleResolution: Bundler` (imports without extensions). Node ≥ 20 at runtime; use `node:` prefixed builtins in new files.
- No new runtime dependencies. Existing: `sql.js`, `minisearch`, `minimatch`, optional peer `@xenova/transformers`. `@opencode-ai/sdk` is removed from `dependencies` by the retire agent.
- sql.js usage: `db.prepare(sql)` → `stmt.bind(params)` → `stmt.step()` / `stmt.getAsObject()` → **always** `stmt.free()` (try/finally). `db.run(sql, params)` for writes. `db.exec` only for multi-statement DDL. Transactions and savepoints are plain SQL (`BEGIN`, `SAVEPOINT sp_n`, `RELEASE`, `ROLLBACK TO`).
- Time is injected: every function that stamps or compares time takes `now: string` (ISO) or `clock: () => string`; tests never depend on wall-clock.
- Hooks never throw to the host: catch everything, log one line to `logs/hooks.log`, print `{}` (or nothing on Stop/PreCompact/SessionEnd), exit 0. Hooks never open SQLite, never import `sql.js`, `minimatch`, `@xenova/transformers`; `minisearch` only through a lazy `import()` in `prompt`/`session-start`.
- File formats are snake_case (ledger, queue, snapshot, config); repository records are camelCase; the mapping happens in repositories and the snapshot builder only.
- Tests: vitest, files under `test/`, name `test/<area>-<topic>.test.ts`. Use `test/helpers/create-test-db.ts` (runs all migrations in memory) for DB tests; add helpers under `test/helpers/` when several files need them. Legacy fixtures live in `test/fixtures/legacy-db/`.
- Definition of done for every agent: `npx tsc --noEmit -p tsconfig.json` shows **no errors in files you own** (errors in other agents' in-flight files are reported, not fixed), `npx vitest run <your test files>` is green, and you return the structured report. Do not run `npm run build` (tsup) unless your brief says so. Never `git commit`.
- Ownership is strict: edit only the files listed for you. If you believe another agent's file must change, describe the change in `cross_module_requests` of your report instead of editing it. New files you create inside your area are yours.
- Read the spec sections cited in your brief; skim the rest only if a question is not answered there. Do not paste large files into your reasoning; grep and read ranges.
