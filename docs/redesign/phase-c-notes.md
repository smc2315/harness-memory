## C1 CLI commands (review, proposals, memory:*, queue, extract, dream, trace, import)

### API notes
  - Every C1 command is a module src/cli/commands/<name>.ts exporting `<name>Options: OptionSpecs` + `run<Name>(ctx)`, registered in src/cli/registry.ts; all 33 commands now have `run` except eval:live. Exit codes: 0 ok, 1 state/domain error (not found, wrong status, duplicate, no database), 2 usage (missing arg, bad enum, needs --yes), 75 LockBusyError via the dispatcher's describeFailure. Every command supports --json (one JSON document, the report type exported from the module) and prints text otherwise.
  - src/cli/lib/cli-error.ts: `CliInputError(message, {exitCode?: 1|2, hint?})`, `usageError(message, hint?)` (exit 2), `describeDomainError(error)` maps MemoryNotFoundError / InvalidMemoryTransitionError / AuthorityViolationError / DuplicateMemoryContentError to {message, hint}, `guard(ctx, body)` wraps a command body and turns those into one stderr line + exit code (other errors propagate to the dispatcher).
  - src/cli/lib/db-access.ts: `requireDatabase(ctx)` (mutations never create memory.sqlite; install/db:migrate do), `readDb(ctx, fn)` = Store.read refusing migrationNeeded/newerThanCode with hints, `writeDb(ctx, {purpose, kind, subject, opId?: string | (value, now) => string}, body, noopWhen?)` = one Store.withWriteLock session returning WriteOp {id: opId ?? cliOpId(kind, subject, now) = `<kind>:<subject>:<now>:<8-hex nonce>`, noop:false, wrote:true} (noopWhen(value) → {id:null, noop:true, wrote:false}, nothing saved). Proposal decisions use `decision:<proposalId>:<now>` (decisionOpId in commands/proposals.ts) and batches `decision:all:<kind>:<now>` as B1 asked.
  - src/cli/lib/lookup.ts: `resolveMemory(db, ref)` / `resolveProposal(db, ref)` accept a full id or a unique prefix (≥ 4 chars, LIKE on the table; ambiguous → CliInputError listing candidates); `shortId(id)` = first 8 chars (what every table prints).
