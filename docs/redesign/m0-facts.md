# M0 facts confirmed on a real machine (2026-11-08)

Machine: Windows 11 Home 26200, Node 24.14.0, npm 11.9.0, Claude Code 2.1.172 (winget `claude.exe`) and
2.1.317 (desktop-bundled, `CLAUDE_CODE_EXECPATH`). Codex not installed. These facts extend
`design-candidates/host-hook-facts.md` and override the spec where they differ.

| # | Fact | Consequence for the implementation |
|---|---|---|
| 1 | A detached child (`spawn(process.execPath, …, {detached:true, stdio:'ignore', windowsHide:true}).unref()`) survives its parent's exit on Windows (Node parent). | Worker and embedding helper use exactly this shape. Survival under the real `claude` hook runner is re-checked by `doctor`'s install self-test (hook spawns a marker-writing child, doctor reads the marker). |
| 2 | `claude -p` in 2.1.172 accepts `--output-format json`, `--json-schema`, `--tools`, `--disallowedTools`, `--strict-mcp-config`, `--no-session-persistence`, `--settings <file-or-json>`, `--model`, `--bare`, `--permission-mode`. **`--max-turns` does not exist.** | Extraction command drops `--max-turns 1` (no tools ⇒ one turn anyway). |
| 3 | Nested `claude -p` from inside a Claude Code process, with the inherited env or with an allowlisted env, returned `{"type":"result","is_error":true,"result":"Not logged in · Please run /login"}` (exit 1, 1–2 s) for both binaries. `claude auth status` → `loggedIn:false`. The standalone CLI on this machine has never been logged in; the desktop app authenticates through its host, not through CLI credentials. | New probe/run status `not_logged_in` (match `/not logged in/i` in `result`). `doctor`/`status` print "run `claude` once in a terminal and `/login`". Episodes stay `queued`; probe is daily so there is no retry storm. **Live extraction could not be exercised in this session; the replay provider covers tests.** |
| 4 | Node and `claude.exe` both start with only `PATH, SystemRoot, TEMP, TMP, USERPROFILE, APPDATA, LOCALAPPDATA, ComSpec, PATHEXT` in the environment. Node's `spawn("claude")` (no shell) resolves `claude.exe` through PATHEXT. | `providerEnv()` allowlist is sufficient on Windows; add `windir`, `HOMEDRIVE`, `HOMEPATH`, `ProgramData`, `ProgramFiles`, `NUMBER_OF_PROCESSORS`, `LANG`, `LC_ALL`, `SHELL`, `TERM`, `HOME`, `XDG_*` when present. No shell is needed to launch `claude`. (`env -i` under Git Bash crashes Node at init — irrelevant to the Node-side allowlist.) |
| 5 | `module.enableCompileCache` is a function on Node 24. | `dist/hook.js` launcher enables it when present. |
| 6 | Hooks spawned by the desktop app carry `CLAUDE_CODE_EXECPATH` (absolute path of the running `claude.exe`). | Binary resolution order for the provider: `HARNESS_MEMORY_CLAUDE_BIN` → `CLAUDE_CODE_EXECPATH` (only if the file exists) → `claude` on PATH → winget package dir. `providerEnv()` must still strip `CLAUDE*`; the path is read before stripping. |
| 7 | `-p` JSON envelope keys: `type:"result"`, `subtype`, `is_error`, `result` (string), `session_id`, `structured_output` (absent on error), `permission_denials`, `modelUsage`, `total_cost_usd`, `duration_ms`, `num_turns`, `terminal_reason`. | Provider parses `structured_output`; missing ⇒ `invalid_output` unless `is_error` text classifies as `not_logged_in` / nested refusal. |
| 8 | Real v0.5 installs on this machine are at `user_version` 9 and 10, not 16 (`test/fixtures/legacy-db/*.sqlite`). | Migration chain 010–021 must run from those versions; fixtures assert zero row loss. Legacy `.conversation-buffer.json` / `.dream-extract-state.json` files exist in `.harness-memory/` and are removed by `uninstall --purge` only. |
| 9 | Existing suite: 31 files / 316 tests green on `master` (includes gitignored `test/tmp-debug.test.ts`). | Regression floor for every phase. |

Still open (needs a logged-in CLI or a second machine): `--tools ""` + `--json-schema` coexistence under a successful run; exec-form hook registration minimum version (install writes exec-form for ≥ 2.1.0 and shell-form otherwise until confirmed); `-p` Manual-mode auto-deny of `ask`; native auto-memory disable key; detached survival under the real hook runner; Codex and OpenCode items from the spec's §15.2.

## Addendum (2026-11-08, from the official hooks/settings/memory/env-vars docs; "inference" marked)

| # | Fact | Consequence |
|---|---|---|
| 10 | Exec-form command hooks exist: `{"type":"command","command":"<exe>","args":[...],"timeout":<seconds>}`; with `args` present the command is spawned directly with no shell. On Windows `command` must be a real `.exe` (`.cmd`/`.bat` shims need shell form). A `shell` field (`"bash"` \| `"powershell"`) exists for shell form and is ignored when `args` is set. Minimum version ≈ 2.1.139 (inference from release mirrors, not the official changelog). | `install` writes exec form with `process.execPath` (node.exe) + `args` when `claude --version` ≥ 2.1.139; otherwise shell form with `"shell":"bash"` when Git Bash exists, else `"powershell"`. |
| 11 | `prompt_id` is a common stdin field on **all** hook events (UUID of the current prompt; absent before the first input). | Every hook can stamp `turn_key = prompt_id` directly; the state file's `turn_key` is only the fallback (`'p:' + session_key + ':' + offset`). |
| 12 | `SessionStart.source ∈ {startup, resume, clear, compact, fork}`; `SessionEnd.reason ∈ {clear, resume, logout, prompt_input_exit, other}`; `permission_mode ∈ {default, plan, acceptEdits, auto, dontAsk, bypassPermissions}` but it is not present on every event. | Treat a missing `permission_mode` as `default`; add `auto` to the non-interactive downgrade set alongside `dontAsk`/`bypassPermissions` only if dogfood shows `ask` is auto-denied there (keep as a config option, default off). |
| 13 | PreToolUse `permissionDecision ∈ {allow, deny, ask, defer}`; precedence across hooks deny > defer > ask > allow; `permissionDecisionReason` is shown to the user for `ask` and to Claude for `deny`; `defer` requires `-p` mode. `additionalContext` is "added to Claude's context alongside the tool result". | Matches the spec's ladder; never emit `defer`. |
| 14 | UserPromptSubmit output uses `hookSpecificOutput.additionalContext`; a top-level `decision: "block"` (or exit 2) blocks the prompt. | We never block prompts. |
| 15 | Default command-hook timeout 600 s; 30 s on UserPromptSubmit / PreModelSwitch / PostModelSwitch; SessionEnd hooks share 1.5 s (raised by a per-hook `timeout` up to 60 s); Stop has no special limit (600 s, inference); Stop continuation capped at 8. | Register PreToolUse/PostToolUse with `timeout: 5`, SessionEnd `timeout: 1`, others `timeout: 10` as in spec §8.2. |
| 16 | Native auto-memory is disabled by settings key `autoMemoryEnabled: false` or env `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`; `disableAllHooks` is a documented settings key and `--settings '<json>'` takes precedence over project/local settings. Hooks appear to run in `-p` mode (inference). | The `claude` provider passes `--settings '{"disableAllHooks":true,"autoMemoryEnabled":false}'` and adds `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` to the otherwise-allowlisted child env. |
| 17 | `.claude/settings.local.json` supports `hooks`; Claude Code adds `**/.claude/settings.local.json` to the global git excludes only when it writes the file itself. | `install` adds the path to `.git/info/exclude` (already planned). |
| 18 | Additional events exist (PostCompact, CwdChanged, FileChanged, WorktreeCreate/Remove, PermissionDenied, InstructionsLoaded, PostToolBatch, …). | Not registered in v1. |
